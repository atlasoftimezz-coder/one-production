01 / The system

One app per workstation.

The architecture is a local application with optional helper processes and external services. FastAPI wires the services together; projects and databases live on disk. Coworkers use their own installations and accounts. There is no shared team backend or distributed job queue in this repository.

Browser → FastAPI

Single-page UI served at 127.0.0.1. The launcher chooses a free port starting at 8730.

Files + SQLite

Project files, JSON state, JSONL chat, usage accounting and searchable knowledge.

Tools as adapters

Official AI clients, Resolve, voice/image sidecars, stock APIs and optional Google services.

Your team’s operating model: voice generation runs on your coworkers’ computers. This PC does not need the local voice engine. A finished voiceover must still be associated with an episode before editing; cross-machine audio import is an integration gap described below.

04 / Production flow

From an idea to an upload bundle.

Script Studio prepares a finished script. The episode orchestrator then runs five stages, using shared run/worker machinery, measured checks and creative review.

01 / SCRIPT

Write & review

Competitor captions → style analysis → FacelessOS writer → scored reviewer loop. A supplied script works too.

02 / COWORKERS

Make the voice

Generate narration elsewhere, read-check it, master the audio and create subtitles. Transfer to the editing project.

03 / VISUALS

Design & build

Art direction + timed shot plan → Fusion scripts → stills and shot QA. Optional scene plates, stock and sound effects.

04 / RENDER

Render & measure

Resolve renders a draft automatically, or the owner supplies a render. Check duration, sync, black frames and resolution.

05 / PACKAGE

Review & deliver

Video, SRT, thumbnail, title options, description, chapters and metadata. Copy to configured storage when requested.

Existing behavior

Two episode modes

  • Draft: own-shot scripts run within a scoped policy; Resolve renders automatically. Some failed checks become review flags.
  • Review-driven: shot scripts use approval cards; the owner renders and selects the file before packaging.
  • Hard failures such as unreadable script, failed voiceover, unavailable Resolve or failed render still stop a draft.
Team handoff to implement

External narration needs an entry point

The existing reuse picker accepts a completed voice_job belonging to the current project. Uploading a WAV and SRT does not itself create that job.

A suitable extension is “Import finished voiceover”: audio + SRT + source script, validation and job registration. This is a proposed change; no remote voice job dispatch exists today.

What “learning” means here

Competitor profiles, explicit directions, verified execution recipes and approved retention lessons are stored and retrieved as context for later AI calls. The application does not train or fine-tune model weights.

Local state, explicit boundaries.

The local-first design keeps project state separate from source code. Selected providers and services still receive the data required for their operations.

06 / Takeover status

Implemented does not mean finished.

The repository records approvals through P6. Later phases have code and automatic checks, with outstanding manual validation. The latest handoff is more current than its older historical sections.

01

Coworker audio handoff

Your operating model separates voice production from editing. The automated episode route currently requires a finished job in the same project; add an import/register path or validate a complete project-transfer workflow.

02

Recover the local motion-kit branch

Main contains Fusion kit v4. The handoff reports an unpushed v5 branch, wip/pro-motion-kit, whose first render failed. That branch is not available in this clone.

03

Improve output quality

The latest handoff records unsatisfactory floating objects/icon tiles and ghosted text. Scene plates were added, but a complete new draft remained pending. Voice loudness and subtitle-end timing also need attention on the coworkers’ voice setup.

04

Ship the image module

The package builder’s copy list omits imagegen/, although runtime installation and launch paths need its files. This is a source-level packaging gap.

05

Validate integrations and release behavior

Real Google Drive connectivity, optional Google sign-in, retention learning, team limits and fresh-PC setup still have outstanding checks. Storyblocks and research workers are not implemented. Choose update hosting and refresh the version/docs before release.

Verification scope: core development dependencies are installed and dependency compatibility passes. This artifact’s navigation, component map, search, filters and mobile layout passed a headless Chrome check. The application’s full test gate is incomplete: it stalled in P4 fake voice test teardown and was stopped; see the takeover report. Automated tests largely isolate real accounts, Resolve, Google and GPU workloads using stand-ins. No paid AI call or GPU render was used to create this artifact.
